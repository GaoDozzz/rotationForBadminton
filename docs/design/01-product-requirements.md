# 产品需求与业务规则

## 1. 产品目标

「转转接龙」服务于羽毛球临时组局和自由轮转，解决四个问题：

1. 报名顺序、候补转正和临时退出难管理。
2. 搭档和对手靠人工安排，容易重复或不公平。
3. 现场不知道谁上场、谁休息、下一场是谁。
4. 比分和个人表现散落在聊天记录中，无法复盘。

首版成功标准是：组织者能够在一个小程序内完成“发起—报名—排阵—开赛—计分—排名—复盘”的闭环。

## 2. 用户角色

| 角色 | 能力 |
|---|---|
| 访客 | 查看允许公开的球局信息，登录后报名 |
| 普通用户 | 管理个人资料、报名/取消、查看赛程和排名 |
| 参赛者 | 查看本人的当前/下一场，为本人参与的比赛录入待确认比分 |
| 裁判 | 认领或被分配比赛，录入待确认比分 |
| 组织者 | 管理球局、名单、赛程、裁判、比分和球局状态 |

组织者代报名生成“未绑定参赛者”。该记录保留代报名人和创建时间；首版不提供复杂的公开认领流程，组织者可在开赛前绑定或更正资料。

## 3. 首版范围

### 3.1 包含

- 微信登录和个人资料。
- 球局创建、编辑、分享、取消和历史记录。
- 正式报名、候补、取消、自动转正和代报名。
- 名单排序、移除、恢复、迟到/暂停/退出标记。
- 自由转赛程生成、预览、重生成、人工交换和锁定。
- 当前场、下一场、休息人员、已完成比赛展示。
- 裁判认领/分配、比分录入、确认和授权改单。
- 实时个人积分和排名、比赛明细、赛后复盘。
- 操作审计、并发控制、断网重试和消息实时同步。

### 3.2 不包含

- 微信支付、退款、AA 结算和发票。
- 俱乐部会员、储值和商业营销。
- 八人转、带飞转的可用算法；仅保留玩法类型和扩展字段。
- 跨球局段位、长期积分和公开总榜。
- 淘汰赛、团体赛、单打、多局两胜。

## 4. 球局配置

### 4.1 基础信息

- 名称、日期、开始时间、预计结束时间。
- 球馆名称、文字地址、经纬度、场地号、场地数。
- 正式人数上限、候补人数上限。
- 水平要求、性别要求、补充说明。
- 费用可作为纯文字/金额信息展示，但不产生支付单。

### 4.2 报名规则

- 报名开始、报名截止、取消截止。
- 是否允许用户自行取消。
- 是否允许组织者代报名。
- 是否允许空降；首版默认不允许。
- 性别必填，水平选填。
- 用户不能在同一球局拥有两个有效报名；代报名人员除外。

### 4.3 比赛规则

- 玩法：首版固定为 `FREE_ROTATION`。
- 分制：11、15 或 21。
- 结束规则：`FIRST_TO` 或 `DEUCE_WITH_CAP`。
- 21 分默认 `DEUCE_WITH_CAP`，封顶 30 分。
- 每人目标场次、并行场地数、性别组合限制和算法偏好。

## 5. 报名和候补

1. 用户提交报名时，服务端锁定球局名额并检查截止时间和重复报名。
2. 正式区未满时进入正式区；已满时按提交成功顺序进入候补区。
3. 正式参赛者在允许取消的时间内取消后，最早的有效候补自动转正。
4. 自动转正与取消必须处于同一数据库事务中。
5. 超过取消截止后，普通用户不能自行退出，只能向组织者申请，由组织者处理。
6. 开赛后新增人员默认不自动修改现有赛程，必须进入“重排预览”。

## 6. 赛程生命周期

1. 报名达到至少 4 人后可以生成赛程。
2. 生成时固化参赛者、规则、算法版本和随机种子。
3. 组织者可预览公平度指标、重生成或人工交换未锁定场次。
4. 确认开赛后激活一个赛程版本。
5. 比赛按照场地进入待开始、进行中、待确认、已完成状态。
6. 人员变动需要生成新版本预览；确认后替换尚未开始的部分。
7. 球局结束后锁定最终排名并保留完整比赛记录。

## 7. 计分和排名

### 7.1 比分确认

- 参赛双方、已分配/已认领裁判、组织者可提交比分。
- 首次有效提交进入“待确认”；组织者提交可直接确认。
- 为降低首版复杂度，任一对方参赛者确认后比分生效；组织者可直接确认或驳回。
- 比分生效后比赛进入已完成并更新排名。
- 已确认比分只有组织者能修改，必须填写修改原因。

### 7.2 积分

假设 A 队 21:15 战胜 B 队，净比分差为 6：

- A 队每名球员积分 `+6`。
- B 队每名球员积分 `-6`。
- 所有球员的积分总和始终为 0。

排名不依赖增量缓存作为最终真相；每次确认或修改比分后，服务端根据当前有效比赛重新聚合。

### 7.3 排序

1. 积分降序。
2. 胜场数降序。
3. 总得分降序。
4. 失分升序。
5. 仍相同则并列，下一名采用竞赛排名法，例如 `1, 2, 2, 4`。

### 7.4 弃权

- 比赛开始前退出：该场取消或进入重排，不计成绩。
- 比赛开始后弃权：胜方记为当前分制满分，败方保留当前得分。
- 若启用领先两分，弃权不要求最终比分满足领先两分。
- 弃权记录必须包含弃权方、操作者和原因。

## 8. 非功能需求

- 关键页面常规接口 P95 响应小于 500ms；生成赛程目标小于 3 秒。
- 支持至少 100 人同时访问同一球局、30 人同时抢报名名额。
- 报名、比分和重排操作不得因重试重复执行。
- 服务端时间统一存储为 UTC，客户端按 Asia/Shanghai 展示。
- 关键操作日志至少保留 180 天，比赛结果长期保留。
- 服务端日志不得记录微信登录 code、完整 Token 等敏感信息。
