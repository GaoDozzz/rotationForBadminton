# 权限、安全与异常处理

## 1. 信任边界

- 小程序客户端不可信，所有 ID、角色、比分和状态都需服务端复核。
- openid 仅用于服务端身份映射，不返回客户端。
- 轮转结果、排名和权限均以服务端计算为准。
- WebSocket 只负责通知状态变化，不作为唯一数据来源。

## 2. 登录和会话

1. 小程序调用 `wx.login` 获取一次性 code。
2. 后端向微信接口换取身份并创建/查询用户。
3. 后端签发短期 Access Token 和可轮换 Refresh Token。
4. Access Token 建议 30 分钟过期；Refresh Token 建议 30 天并支持主动失效。
5. Refresh Token 轮换后旧 Token 不可再次使用。

昵称、头像和性别由用户主动填写/选择；不把未授权资料当作微信登录的前置结果。

## 3. 权限矩阵

| 操作 | 参赛者 | 裁判 | 组织者 |
|---|---:|---:|---:|
| 查看球局/赛程/排名 | ✓ | ✓ | ✓ |
| 本人报名和截止前取消 | ✓ | — | ✓ |
| 代报名、移除、转正 | — | — | ✓ |
| 生成/激活/重排赛程 | — | — | ✓ |
| 认领裁判 | 条件允许 | ✓ | ✓ |
| 提交本人比赛比分 | ✓ | ✓ | ✓ |
| 确认对方提交的比分 | ✓ | — | ✓ |
| 修改已确认比分 | — | — | ✓ |
| 结束或取消球局 | — | — | ✓ |

“是参赛者”必须按目标比赛中的 `match_players` 判断，不能只凭用户参加了该球局。

## 4. 数据校验

- 所有 DTO 使用白名单校验并拒绝未知字段。
- 分数必须为非负整数并符合分制规则。
- 名称、备注和修改原因限制长度并进行输出转义。
- 经纬度、人数、场地数、目标场次设置合理上下限。
- 数据库外键、唯一约束和 CHECK 约束作为第二道防线。

建议首版限制：正式人数 4～64、人均目标场次 1～30、场地数 1～16。

## 5. 幂等与并发

- 报名、取消、代报名、生成赛程、激活、重排确认、开赛、提交/确认比分必须带幂等键。
- 同一幂等键搭配不同请求体时返回冲突，不能复用旧响应。
- 球局和比分使用版本号做乐观锁。
- 报名名额和候补转正使用 PostgreSQL 行锁和事务。
- 同一球局只允许一个赛程生成任务；数据库状态仍是最终保护。

## 6. 比分争议

- 双方同时提交相同比分：合并为同一待确认结果。
- 双方提交不同比分：比赛标记 `SCORE_DISPUTED`，禁止自动完成，通知组织者处理。
- 待确认期间比赛不能被重排或再次开始。
- 组织者修改已确认比分后，旧提交保留并重新计算排名。
- 所有比分接口检查 `scoreVersion`，旧页面提交返回冲突并展示当前比分。

## 7. 实时与降级

- WebSocket 事件使用单调递增序号。
- Redis 广播用于多实例同步，但数据库是事实来源。
- 客户端断线后先尝试补事件；无法补齐时重新获取球局快照。
- WebSocket 不可用时，小程序对当前比赛使用短轮询，对其他页面使用用户触发刷新。
- 广播发生在数据库事务提交后，避免客户端读到未提交数据。

## 8. 关键异常处理

| 场景 | 处理 |
|---|---|
| 最后一名额被多人抢 | 事务串行判断，一人正式，其余按顺序候补 |
| 候补转正期间再次有人取消 | 行锁保护，按 `queue_no` 依次处理 |
| 生成赛程时名单变化 | 输入事件版本不一致，生成结果作废 |
| 重排预览后比赛已开始 | 确认返回 409，要求重新预览 |
| 比分提交超时但实际成功 | 同幂等键重试返回原结果 |
| 排名缓存未及时更新 | 响应携带版本，缓存未命中时从有效比分重算 |
| 服务重启 | 进行中状态从数据库恢复，客户端重新订阅 |

## 9. 隐私与合规

- 仅收集实现功能所需的昵称、头像、性别、水平及比赛记录。
- 性别用于配对约束，隐私说明中明确用途。
- 不在日志、埋点或分享参数中暴露 openid、Token 和手机号。
- 分享链接只携带不可猜测的球局 ID/分享码，不携带用户身份凭证。
- 用户注销后按合规要求匿名化账户；已参与比赛中的必要成绩快照保留为匿名参赛者记录。

## 10. 运维基线

- 开发、测试、生产使用独立数据库和微信配置。
- 数据库每日备份，建议保留 7 个日备份和 4 个周备份。
- 数据库迁移只前进，不在生产环境自动回滚破坏性字段。
- 监控登录失败率、接口 P95、5xx、报名冲突、赛程生成失败、WebSocket 在线数。
- 关键告警带 `requestId/eventId`，但不带敏感 Token。
- 发布使用滚动部署；涉及协议不兼容时先发布兼容后端，再发布小程序。
