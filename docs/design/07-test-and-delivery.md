# 测试、验收与开发拆分

## 1. 测试层级

### 单元测试

- 计分合法性、积分和并列排名。
- 球局、报名、比赛状态转换。
- 权限能力集计算。
- 自由转算法硬约束、代价和确定性。

### 集成测试

- PostgreSQL 真实事务下的报名抢位和候补转正。
- 比分确认、改单、排名重算。
- 赛程版本激活和重排冲突。
- Redis 缓存失效与 WebSocket 广播。

### 端到端测试

- 创建球局至赛后复盘完整链路。
- 分享进入、登录、报名和取消。
- 多角色录分、确认与组织者改单。
- 临时退出、预览和确认重排。

### 真机测试

- iOS/Android 微信主流版本。
- 刘海屏、小屏、字体放大和深色系统设置。
- 4G/5G、弱网、切后台、锁屏后返回。
- 分享卡片冷启动和登录态失效恢复。

## 2. 关键验收用例

### 报名

- 30 个并发请求争抢 10 个名额，正式区恰好 10 人，且不存在重复有效报名。
- 正式用户取消后，候补第 1 名自动转正，顺序不受接口重试影响。
- 超过取消截止后普通用户失败，组织者操作成功并留日志。
- 未填写性别的用户不能报名，代报名也必须填写性别。

### 算法

- 4～32 人、1～8 个场地随机生成 10,000 组配置，硬约束零违反。
- 相同输入和种子重复运行得到字节级一致的核心赛程。
- 可精确平均时每人场次数一致；不可精确时最大差为 1。
- 重排后已完成和进行中比赛零变化。
- 不可满足的混双配置返回明确原因，而不是无限计算。

### 计分与排名

- 21:15 后胜方各 +6、败方各 -6，总积分为 0。
- 21 分领先两分规则允许 22:20、30:29，不允许 21:20、31:29。
- 相同积分按胜场、总得分、失分正确排序；完全相同显示并列。
- 两方提交冲突比分后不能自动完成比赛。
- 组织者改单后排名恢复为基于全部最新有效比分的结果。

### 重排

- 退出人员只从未开始比赛移除。
- 预览后若有比赛开始，旧预览无法确认。
- 组织者取消预览时激活赛程完全不变。
- 确认成功后旧版本仍可审计，但普通用户只看到新激活版本。

## 3. 性能验收

- 球局详情 P95 < 500ms，P99 < 1s。
- 30 人并发报名无超卖，错误返回可理解。
- 32 人、8 场地、每人 10 场的赛程生成 < 3s。
- 单球局 100 个 WebSocket 在线连接时比分广播 P95 < 1s。
- 排名聚合在 300 场比赛规模下 P95 < 300ms；必要时使用版本化缓存。

## 4. 开发任务拆分

### Epic A：工程与认证（3～4 人日）

- Monorepo、代码规范、测试和 CI。
- NestJS、PostgreSQL、Redis、数据库迁移。
- 原生小程序 TypeScript 项目和环境配置。
- 微信登录、Token 轮换、个人资料。

### Epic B：球局与报名（6～8 人日）

- 球局 CRUD 和状态机。
- 首页、创建/编辑、球局详情。
- 报名、候补、取消、自动转正、代报名。
- 名单管理、截止规则和分享进入。

### Epic C：赛程算法（8～10 人日）

- 算法输入输出协议和种子随机数。
- 场次数分配、硬约束、候选构造。
- 局部优化、公平度指标、属性测试。
- 赛程生成、预览、人工交换和激活。

### Epic D：对阵与实时状态（5～6 人日）

- 轮次/比赛模型和对阵页。
- 开始比赛、当前/下一场展示。
- WebSocket 房间、事件序号、断线补偿。
- 裁判认领和组织者分配。

### Epic E：计分与排名（5～7 人日）

- 计分器、比分校验和待确认流程。
- 冲突比分、弃权、组织者改单。
- 积分聚合、并列排名和个人统计。
- 比分及操作审计。

### Epic F：动态重排与复盘（4～5 人日）

- 人员状态变化。
- 重排候选版本和差异预览。
- 乐观锁确认和赛程版本切换。
- 球局结束、个人及全局复盘。

### Epic G：发布准备（4～6 人日）

- 真机、弱网、性能和安全测试。
- 隐私政策、用户协议和授权文案。
- HTTPS/WSS 域名、备案和小程序后台配置。
- 体验版验收、审核材料、发布和回滚预案。

## 5. 里程碑

| 里程碑 | 可验收结果 | 累计时间 |
|---|---|---:|
| M1 基础可运行 | 登录、资料、创建球局 | 第 1 周 |
| M2 接龙可用 | 分享、报名、候补和名单管理 | 第 2～3 周 |
| M3 自动排阵 | 算法、预览、激活 | 第 4～5 周 |
| M4 现场闭环 | 对阵、裁判、计分和排名 | 第 6～7 周 |
| M5 发布候选 | 重排、复盘、测试和合规 | 第 8～9 周 |

## 6. Definition of Done

每个功能只有同时满足以下条件才能完成：

- 接口契约、权限和错误码明确。
- 服务端单元/集成测试通过。
- 小程序正常、空、加载、错误状态齐全。
- 重复提交和弱网场景已验证。
- 关键业务操作有审计日志。
- 不引入高优先级安全问题。
- 产品验收用例通过，并更新相关设计文档。

## 7. 开工前置条件

- 微信小程序 AppID、开发者权限和测试账号。
- 后端测试环境、PostgreSQL、Redis 和 HTTPS/WSS 域名。
- 品牌名称、Logo/主色及分享卡片方向。
- 场馆位置是否接入微信地图选点能力的最终确认。
- 隐私政策和用户协议主体信息。
