# 「转转接龙」正式设计基线

版本：v1.0  
状态：已确认，可进入开发  
日期：2026-07-31

## 1. 已确认的产品决策

- 客户端采用原生微信小程序 + TypeScript。
- 后端采用 Node.js + NestJS，数据层采用 PostgreSQL + Redis。
- 首版只实现自由转，人数和场地数自定义；数据结构预留八人转、带飞转等玩法。
- 单场为一局制，支持 11/15/21 分；21 分默认领先 2 分、30 分封顶。
- 排名积分等于比分差：胜方每人增加比分差，败方每人减少比分差。
- 同积分排序：积分、胜场数、总得分、更少失分，仍相同则并列。
- 首版不开发付款、退款和结算。
- 性别必填、水平选填，允许组织者代报名。
- 临时退出只影响未开赛场次；先生成影响预览，再由组织者确认。
- 裁判可选；参赛双方、裁判和组织者可以录分；已确认比分仅组织者可修改。
- 流程参考现有产品，视觉与品牌重新设计。

## 3. 名词约定

- **球局（Event）**：一次由组织者发起的完整活动。
- **轮次（Round）**：同一时间并行进行的一组比赛。
- **比赛（Match）**：某一轮在某一块场地进行的 2 对 2 比赛。
- **参赛者（Participant）**：球局中的人员快照，可关联微信用户，也可由组织者代报名而暂不关联用户。
- **赛程版本（Schedule Version）**：一次完整的对阵生成结果。重排不会覆盖旧版本。
- **积分（Ranking Points）**：个人累计净比分差，不是胜场固定积分。

## 4. 设计原则

- 服务端是报名名额、赛程、比分、排名和权限的唯一可信来源。
- 所有关键写操作必须幂等，并记录操作者和操作时间。
- 已完成比赛不可因重排而改变；已确认比分不可静默覆盖。
- 算法结果必须可复现、可解释、可测试，并允许组织者人工调整。
- 小程序弱网、重复点击和 WebSocket 重连不能造成重复数据。
